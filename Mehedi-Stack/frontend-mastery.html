১. CSS Grid বনাম Flexbox: সঠিক আর্কিটেকচারাল সিদ্ধান্ত

একজন সাধারণ ডেভেলপার যেকোনো কিছুতেই ফ্লেক্সবক্স ব্যবহার করে। কিন্তু ৭+ বছরের সিনিয়র আর্কিটেক্ট লেভেলে নিয়ম হলো:
• Flexbox হলো ১-মাত্রিক (1-Dimensional Layout): হয় কন্টেন্টকে রো (Row) বরাবর অথবা কলাম (Column) বরাবর সাজানোর জন্য। ভেতরের আইটেমের সাইজ অনুযায়ী ফ্লেক্সিবল স্পেসিংয়ের জন্য সেরা।
• CSS Grid হলো ২-মাত্রিক (2-Dimensional Layout): একই সাথে রো এবং কলাম সমন্বয়ে স্ট্যাবল পেজ স্ট্রাকচার বা কার্ড গ্রিড তৈরির জন্য সেরা।

মিডিয়া কুয়েরি ছাড়া রেসপন্সিভ কার্ড গ্রিড (auto-fit & minmax)

কোনো মিডিয়া কুয়েরি কোড না লিখে নিখুঁত স্বয়ংক্রিয় রেসপন্সিভ গ্রিড তৈরির গোল্ড স্ট্যান্ডার্ড: 

.responsive-grid {
    display: grid;
    /* কার্ডের মিনিমাম সাইজ ২৮০ পিক্সেল, বাকিটা সমান ভাগে ফ্লেক্সিবল (1fr) */
    grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
    gap: 1.5rem;
}

auto-fit স্ক্রিনে জায়গা থাকলে কার্ডগুলোকে ফুল-উইডথ প্রসারিত করে, আর auto-fill খালি গ্রিড ট্র্যাক তৈরি করে ফাঁকা জায়গা ধরে রাখে।

ব্রাউজার রেন্ডারিং পাইপলাইন ও জিপিইউ এক্সিলারেশন (GPU Acceleration)

ব্রাউজার যখন একটি ওয়েব পেজ আঁকে, সে ৫টি ধাপ পার করে:
DOM + CSSOM → Render Tree → Layout (Reflow) → Paint (Repaint) → Composite.

  • Layout (Reflow): width, height, top, left, margin পরিবর্তন করলে পুরো পেজের উপাদানগুলোর অবস্থান পুনরায় পরিমাপ করতে হয়। এটি সবচেয়ে ভারী এবং সিপিইউ খরচ করে।
  • Paint (Repaint): color, background-color পরিবর্তন করলে রিফ্লো হয় না, তবে নতুন করে পিক্সেল আঁকতে হয়।
  • Composite (Zero Layout/Paint): শুধুমাত্র transform (translate, scale, rotate) এবং opacity পরিবর্তন করলে ব্রাউজার সিপিইউ বাদ দিয়ে সরাসরি GPU (Graphics Card) লেয়ারে কাজ করে। ফলে ৬০ FPS স্মুথ অ্যানিমেশন পাওয়া যায় কোনো ল্যাগ ছাড়াই!
সিনিয়র টিপ: অ্যানিমেশনে কখনো top/left ব্যবহার করবেন না, সবসময় transform: translate3d() ব্যবহার করুন।

২. jQuery এন্টারপ্রাইজ মেইনটেন্যান্স, মেমোরি লিক ও অপ্টিমাইজেশন

বিশ্বের লাখ লাখ বড় এন্টারপ্রাইজ সিস্টেমে এখনো বিশাল পরিমাণ jQuery কোড সচল রয়েছে। একজন ৭+ বছরের ফুলস্ট্যাক ইঞ্জিনিয়ারকে এই সিস্টেমগুলো মেইনটেইন ও আধুনিকীকরণ করার মতো দক্ষ হতে হবে।

❌ অপেশাদার কোড (Memory & CPU Disaster)
// প্রতি ক্লিকে নতুন করে পুরো ডোম ট্রাভার্স
for(var i=0; i < 1000; i++) {
    $('#cart-total').text(i);
}
// প্রতি নতুন উপাদানের জন্য আলাদা হ্যান্ডলার
$('.order-item').on('click', function() { ... });
প্রতি লুপে ডোম রি-কোয়েরি এবং হাজার হাজার ইভেন্ট লিসেনার র‍্যাম জ্যাম করে দেয়।
✅ সিনিয়র অপ্টিমাইজড কোড
// ১. সিলেক্টর ক্যাশ করে রাখা
var $cartTotal = $('#cart-total');
$cartTotal.text(finalTotal);

// ২. Event Delegation (সিঙ্গেল প্যারেন্ট লিসেনার)
$(document).on('click', '.order-item', function(e) {
    var $target = $(this);
});
ডায়নামিক আইটেম আসলেও নতুন লিসেনার বানাতে হয় না; ১টি লিসেনারই সব সামলায়।
jQuery তে Memory Leak কেন ঘটে?

যখন আপনি কোনো DOM এলিমেন্ট স্ক্রিন থেকে মুছে দেন (যেমন $('#container').html('') অথবা .remove()), কিন্তু জাভাস্ক্রিপ্ট ক্লোজার (Closure) বা গ্লোবাল ভ্যারিয়েবলে সেই এলিমেন্টের রেফারেন্স রয়ে যায়, তখন গার্বেজ কালেক্টর মেমোরি ক্লিয়ার করতে পারে না। একে বলে Detached DOM Tree Leak। SPA বা লং-রানিং ড্যাশবোর্ডে সারাদিন কাজ করলে ব্রাউজার গিগাবাইট মেমোরি খেয়ে ক্র্যাশ করে।
সমাধান: উপাদান সরানোর আগে সবসময় $el.off() দিয়ে ইভেন্ট আনবাইন্ড করুন এবং রেফারেন্স $el = null; করে দিন।

৪. Angular Signals বনাম RxJS: কখন কোনটি ব্যবহার করবেন?

ইন্টারভিউতে হট প্রশ্ন: "অ্যাঙ্গুলারে Signals আসার পর RxJS কি মৃত?"
একজন অভিজ্ঞ লিড আর্কিটেক্টের উত্তর হবে: "না! তারা পরস্পরের পরিপূরক।"

বৈশিষ্ট্য Angular Signals RxJS Observables
মডেল Synchronous Reactive State (সর্বদা বর্তমান ভ্যালু থাকে) Asynchronous Event Stream (সময়ের সাথে ডাটার প্রবাহ)
ব্যবহার ক্ষেত্র কম্পোনেন্ট স্টেট, ফর্ম ফিল্ড রিঅ্যাক্টিভিটি, ড্রাইভেন প্রোপার্টিজ HTTP রিকোয়েস্ট, Debounce/Search টাইপিং, WebSockets, জটিল ইভেন্ট অর্কেস্ট্রেশন
আনসাবস্ক্রাইব দরকার? না! কোনো মেমোরি লিক রিস্ক নেই (স্বয়ংক্রিয় ক্লিনআপ) হ্যাঁ! takeUntilDestroyed() বা async pipe আবশ্যক
RxJS ৪টি Flattening Operators (যেগুলো ইন্টারভিউতে নিশ্চিত জিজ্ঞেস করা হয়)
  • switchMap: নতুন ইভেন্ট আসলে আগের চলমান রিকোয়েস্ট বাতিল (Cancel) করে দেয়। সার্চবক্স এবং ইউজার রাউট চেঞ্জে সেরা।
  • concatMap: সিরিয়াল কিউ (Queue)। আগের কাজটি শেষ না হওয়া পর্যন্ত পরবর্তী কাজটি শুরু করে না। অর্ডার/পেমেন্ট ট্রানজ্যাকশনে জরুরি।
  • mergeMap: সমান্তরাল (Parallel)। সব রিকোয়েস্ট একসাথে ব্যাকগ্রাউন্ডে চালিয়ে দেয়। কোনো অর্ডার রক্ষা করার প্রয়োজন না থাকলে সেরা।
  • exhaustMap: যদি বর্তমানে কোনো রিকোয়েস্ট প্রসেসিংয়ে থাকে, তাহলে নতুন কোনো ইভেন্ট গ্রাহ্যই করে না (ইগনোর করে)। ফর্ম সাবমিট / সেভ বাটনে ডাবল-ক্লিক স্প্যাম প্রতিরোধ করতে অসাধারণ।

৫. Change Detection: Default বনাম OnPush ও Zoneless মেকানিক্স

অ্যাঙ্গুলারের ডিফল্ট চেঞ্জ ডিটেকশনে Zone.js ব্রাউজারের প্রতিটি ইভেন্ট (ক্লিক, টাইমার, HTTP কল) ইন্টারসেপ্ট করে এবং পুরো কম্পোনেন্ট ট্রির শুরু থেকে শেষ পর্যন্ত প্রতিটি কম্পোনেন্ট রি-চেক করে। অ্যাপ বড় হলে এটি মারাত্মক স্লো হয়ে যায়।

ChangeDetectionStrategy.OnPush এর কার্যপদ্ধতি

OnPush ব্যবহার করলে অ্যাঙ্গুলার শুধুমাত্র তখনই কম্পোনেন্ট রি-রেন্ডার করে যখন:

  1. কোনো @Input() প্রোপার্টির অবজেক্ট রেফারেন্স পরিবর্তন হয় (ইমিউটেবল ডাটা)।
  2. কম্পোনেন্টের নিজের ভেতরে কোনো ডোম ইভেন্ট ফায়ার হয় (যেমন ইউজার ক্লিক)।
  3. টেমপ্লেটে কোনো সিগন্যাল রিড করা হচ্ছে যার মান পরিবর্তন হয়েছে।
  4. ম্যানুয়ালি ChangeDetectorRef.markForCheck() কল করা হয়।

Zoneless Angular (ভবিষ্যতের স্ট্যান্ডার্ড): Angular 18 এ Zone.js সম্পূর্ণ সরিয়ে সিগন্যাল-ড্রাইভেন সরাসরি রেন্ডারিং চালু করা হয়েছে, যা মেমোরি ফুটপ্রিন্ট এবং ফ্রেম রেট নাটকীয়ভাবে বৃদ্ধি করেছে।

৬. @defer লেজি লোডিং এবং HTTP Interceptors

Angular 17+ এর সবচেয়ে যুগান্তকারী ফিচার হলো @defer (Deferrable Views)। এটি কোনো পেজের নিচের অংশের হেভি কম্পোনেন্টকে (যেমন চার্ট বা কমেন্ট বক্স) মূল বান্ডেলে লোড না করে তখন লোড করে যখন ইউজার স্ক্রোল করে সেই সেকশনে পৌঁছায়! 

@defer (on viewport; prefetch on idle) {
    <app-heavy-analytics-chart [data]="analyticsData" />
} @placeholder {
    <div class="chart-skeleton-loader">চার্ট লোড হচ্ছে...</div>
} @loading (minimum 500ms) {
    <app-spinner />
}
এন্টারপ্রাইজ Auth Token Refresh Interceptor

এন্টারপ্রাইজ সিস্টেমে HttpInterceptorFn এর দায়িত্ব হলো প্রতিটি আউটগোয়িং রিকোয়েস্টে বেয়ারার টোকেন ইনজেক্ট করা। আর সার্ভার যদি 401 Unauthorized রিটার্ন করে, তখন ইন্টারসেপ্টর একটি রিফ্রেশ টোকেন এপিআই কল করে নতুন টোকেন সংগ্রহ করবে এবং ইন-ফ্লাইট আটকে থাকা অন্যান্য সমস্ত রিকোয়েস্টকে কিউ (Queue) করে রি-ট্রাই করবে।

অ্যাঙ্গুলার রিঅ্যাক্টিভিটি টেস্ট

একটি ই-কমার্স অ্যাপের সার্চ ইনপুট বক্সে ইউজার দ্রুত টাইপ করছেন। প্রতিটি কি-স্ট্রোকের সাথে সার্ভার এপিআই কল করার ক্ষেত্রে কোন RxJS পাইপলাইন মেমোরি লিক ও রেস-কন্ডিশন মুক্ত?

ব্যাখ্যা:

সহীহ উত্তর B! debounceTime(300) ইউজারের টাইপিং বিরতি পর্যন্ত অপেক্ষা করে সার্ভার কল কমায়; distinctUntilChanged() একই শব্দে অপ্রয়োজনীয় কল ঠেকায়; switchMap আগের চলমান স্লো রিকোয়েস্ট ক্যানসেল করে রেস কন্ডিশন দূর করে; এবং takeUntilDestroyed() কম্পোনেন্ট ডেস্ট্রয় হলে সাবস্ক্রিপশন স্বয়ংক্রিয় ক্লিনআপ করে মেমোরি লিক ঠেকায়।
