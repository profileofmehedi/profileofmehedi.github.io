লেকচার ০১ • মূল ভূমিকা

AWS IAM কী এবং কেন এটি ক্লাউডের প্রধান দারোয়ান?

ক্লাউড সিকিউরিটির প্রথম ও প্রধান ধাপ হলো IAM। এটি নির্ধারণ করে—কে আপনার ক্লাউডে প্রবেশ করতে পারবে এবং কী করতে পারবে।

🛡️ দুইটি মূল স্তম্ভ (Two Pillars):

  • Authentication (পরিচয় যাচাই): আপনি আসলে কে? (Username + Password + MFA দিয়ে নিশ্চিত হওয়া)।
  • Authorization (অনুমতি যাচাই): আপনি কোন কোন AWS রিসোর্সে (যেমন EC2, S3, RDS) কাজ করার ক্ষমতা রাখেন?
⭐ গোল্ডেন রুল (পরীক্ষার জন্য মাস্ট):
IAM হলো একটি Global Service! অর্থাৎ আপনি যখন IAM-এ কোনো ইউজার বা রোল বানাবেন, তার জন্য কোনো Region সিলেক্ট করতে হয় না। এটি পুরো অ্যাকাউন্টে বিশ্বব্যাপী প্রযোজ্য।

🎯 কেন IAM এতো গুরুত্বপূর্ণ?

ক্লাউডে ডেটা লিক হওয়া বা সার্ভার হ্যাক হওয়ার প্রধান কারণ ভুল পারমিশন কনফিগারেশন। IAM নিশ্চিত করে Principle of Least Privilege (ন্যূনতম প্রয়োজনীয় অধিকার)।

লেকচার ০২ • আইডেন্টিটি বিভাজন

রুট অ্যাকাউন্ট বনাম আইএএম ইউজার (Root vs IAM User)

কেন কখনোই রুট অ্যাকাউন্ট দিয়ে অফিসের সাধারণ কাজ করবেন না? পরীক্ষার অতি প্রিয় একটি প্রশ্ন!

👑 AWS Root User (সুপার পাওয়ার):

  • অ্যাকাউন্ট খোলার সময় যে ইমেইল ও পাসওয়ার্ড দেওয়া হয়, সেটাই রুট অ্যাকাউন্ট।
  • এর ক্ষমতা সীমাহীন (God-level Access)। কোনো IAM Policy দিয়ে একে আটকানো যায় না।
  • AWS Best Practice: অ্যাকাউন্ট খোলার পরপরই রুট ইউজারে Hardware/Virtual MFA অন করবেন এবং এর কোনো Access Key তৈরি করবেন না!

👤 IAM User (প্রাত্যহিক কর্মী):

  • প্রতিটি আসল মানুষের জন্য ১টি করে আলাদা IAM User খুলতে হবে।
  • ডিফল্টভাবে নতুন ইউজারের Zero Permission (কোনো অ্যাক্সেস নেই) থাকে।
  • প্রয়োজনমাফিক পলিসি দিয়ে তাকে নির্দিষ্ট কাজের অনুমতি দেওয়া হয়।
🚨 এক্সাম অ্যালার্ট: যদি প্রশ্নে বলে "An engineer accidentally pushed AWS root credentials to GitHub"—প্রথম কাজ হবে রুট পাসওয়ার্ড পরিবর্তন ও অ্যাক্সেস কি ডিলিট করে সব সেশন বন্ধ করা।

লেকচার ০৩ • টিম ম্যানেজমেন্ট

আইএএম গ্রুপস (IAM Groups) — দলগত পারমিশন নিয়ন্ত্রণ

প্রতিটি ইউজারের কাছে আলাদা করে পারমিশন না দিয়ে কীভাবে এক ক্লিকে ৫০ জনের অনুমতি হ্যান্ডেল করবেন?

👥 গ্রুপ কীভাবে কাজ করে?

  • গ্রুপ হলো একাধিক IAM User-এর একটি কালেকশন বা দল (যেমন: DevOps-Team, DBA-Admins, Audit-Staff)।
  • পলিসি সরাসরি গ্রুপে অ্যাসাইন করবেন, আর গ্রুপের সব মেম্বার স্বয়ংক্রিয়ভাবে সেই পারমিশন পেয়ে যাবে।
⚠️ এক্সামের জন্য অত্যন্ত গুরুত্বপূর্ণ ৩টি নিয়ম:
১. গ্রুপের নিজস্ব কোনো লগইন নেই: গ্রুপ কোনো আইডেন্টিটি নয়, এটি শুধুমাত্র ইউজার ধারণ করে।
২. নেস্টিং নিষিদ্ধ (No Nested Groups): গ্রুপের ভেতরে অন্য গ্রুপ ঢোকানো যায় না (Group inside Group is NOT allowed)।
৩. একজন ইউজার একাধিক গ্রুপে থাকতে পারে: যেমন একজন ডেভেলপার একইসাথে Dev-Team এবং Release-Managers গ্রুপে থাকতে পারেন।
INFOGRAPHIC 3.0
লেকচার ০৪ • সবচেয়ে গুরুত্বপূর্ণ টপিক

আইএএম রোলস (IAM Roles) ও ইনস্ট্যান্স প্রোফাইল

অ্যাপ্লিকেশন বা সার্ভারকে পারমিশন দেওয়ার ক্ষেত্রে IAM Role হলো AWS-এর সবচেয়ে নিরাপদ সমাধান!

🔑 IAM Role কী?

রোল হলো একটি অস্থায়ী আইডেন্টিটি যার কোনো পার্মানেন্ট সিক্রেট কি থাকে না। AWS STS (Security Token Service)-এর মাধ্যমে এটি সাময়িক সময়ের জন্য (১ ঘণ্টা থেকে ১২ ঘণ্টা) টোকেন প্রদান করে।

🖥️ EC2 Instance Profile কীভাবে কাজ করে?

যদি আপনার EC2 সার্ভারের ভেতর চলমান কোডকে S3 বা DynamoDB-তে ডেটা সেভ করতে হয়, তবে কোডের মধ্যে Access Key হার্ডকোড করবেন না! বরং EC2-তে একটি IAM Role যুক্ত করে দেবেন।

💡 এক্সাম ক্লু: প্রশ্নে যখনই দেখবেন "Least operational overhead" এবং "Securely grant an EC2 instance access to AWS services"—সরাসরি উত্তর হবে IAM Role (Instance Profile)!

লেকচার ০৫ • পলিসির ব্যবচ্ছেদ

আইএএম পলিসি ও জেএসন (JSON) স্ট্রাকচার

AWS-এ পারমিশন লেখার একমাত্র ভাষা হলো JSON। চলুন এর প্রতিটি পার্ট ভেঙে ভেঙে বুঝি।

📜 JSON পলিসির মূল অঙ্গসমূহ:

  • Version: পলিসির ভাষা সংস্করণ। সবসময় "2012-10-17" দিতে হবে।
  • Effect: অনুমতি দেবেন নাকি আটকাবেন? ("Allow" অথবা "Deny")।
  • Action: কোন সার্ভিসটিতে কী কাজ হবে? (যেমন: "s3:GetObject")।
  • Resource: কোন নির্দিষ্ট রিসোর্সের ওপর অ্যাকশন ঘটবে (ARN)।
  • Condition: কোনো বিশেষ শর্ত (যেমন: শুধুমাত্র MFA অন থাকলে)।
⭐ ওয়াইল্ডকার্ড ট্রিক: "s3:*" দিলে S3 এর সব কাজ করা যাবে। আবার "arn:aws:s3:::my-bucket/*" দিলে ওই বাকেটের ভেতরের সব ফাইলে পারমিশন প্রযোজ্য হবে।
POLICY BLUEPRINT 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "VisualExamPolicy",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::company-reports",
        "arn:aws:s3:::company-reports/*"
      ],
      "Condition": {
        "Bool": {
          "aws:MultiFactorAuthPresent": "true"
        }
      }
    }
  ]
}
📌 ব্যাখ্যা: এই পলিসিটি ইউজারের জন্য S3 বাকেটের ডেটা পড়ার সুযোগ দেবে—কিন্তু শুধুমাত্র যদি ইউজার MFA দিয়ে লগইন করে থাকে!
লেকচার ০৬ • অনুমতি মূল্যায়নের গণিত

পলিসি ইভালুয়েশন লজিক (Policy Evaluation Rules)

যখন একাধিক পলিসি সাংঘর্ষিক হয়, তখন AWS কীভাবে চূড়ান্ত সিদ্ধান্ত নেয়? এটা না জানলে পরীক্ষায় ভুল হবেই!

⚖️ ৩টি সুবর্ণ ক্রম (Decision Flow):

  1. ১. Explicit Deny: যদি কোনো একটি পলিসিতেও লেখা থাকে "Deny", তবে অন্য সব পলিসিতে Allow থাকলেও উত্তর হবে না (DENIED)। এটি সবার উপরে স্থান পায়।
  2. ২. Explicit Allow: যদি কোথাও কোনো Deny না থাকে, এবং অন্তত একটি বৈধ "Allow" থাকে—তবেই অনুমতি মিলবে।
  3. ৩. Default Deny: কোনো Deny-ও নেই, আবার কোনো Allow-ও নেই—তাহলে ডিফল্ট নিয়মে অ্যাক্সেস বন্ধ থাকবে।
🚨 এক্সাম ট্র্যাপ: আপনি IAM ইউজারে ফুল অ্যাডমিন পাওয়ার দিয়েছেন, কিন্তু AWS Organizations-এর SCP দিয়ে ওই অ্যাকাউন্টে S3 ডিলিট করা Deny করা হয়েছে। ইউজার কখনোই S3 ডিলিট করতে পারবে না! কারণ SCP Deny beats IAM Allow!

লেকচার ০৭ • নিরাপত্তা ও নিরীক্ষা

MFA ও সিকিউরিটি অডিটিং টুলস

অ্যাকাউন্টে পাসওয়ার্ড চুরি হলেও কীভাবে ক্লাউড সুরক্ষিত রাখবেন এবং পাসওয়ার্ডের অডিট করবেন?

🔐 Multi-Factor Authentication (MFA) ডিভাইস:

  • Virtual MFA App: Google Authenticator, Microsoft Authenticator (মোবাইলে কোড জেনারেট হয়)।
  • U2F / WebAuthn Hardware Token: YubiKey ফিজিক্যাল কি (সবচেয়ে নিরাপদ)।

🔍 ২টি অপরিহার্য অডিটিং অস্ত্র:

  • IAM Credential Report (অ্যাকাউন্ট লেভেল): একটি CSV ফাইল জেনারেট করে দেখায় কার কার পাসওয়ার্ড ৯০ দিন পুরোনো, কার MFA বন্ধ আছে।
  • IAM Access Analyzer: AI চালিত টুল, যা খুঁজে বের করে আপনার S3 বা KMS অন্য কারো সাথে ভুলবশত শেয়ার করা আছে কিনা।

লেকচার ০৮ • পরীক্ষার চ্যালেঞ্জ

রিয়েল এক্সাম সিনারিও ও ট্র্যাপ সলভার

AWS সার্টিফিকেশন পরীক্ষায় যে ধরনের ধাঁধা দেওয়া হয় এবং অপশন বাদ দেওয়ার মোক্ষম কৌশল।

🎯 সিনারিও ০১: সার্ভার থেকে ক্লাউড ফাইল এক্সেস

প্রশ্ন: একটি EC2 সার্ভার থেকে S3 বাকেটে ফাইল আপলোড করতে হবে। স্ট্যাটিক পাসওয়ার্ড ব্যবহার করা যাবে না। সমাধান কী?

✅ সঠিক সিদ্ধান্ত: একটি IAM Role তৈরি করে EC2 Instance Profile হিসেবে এটাচ করতে হবে।

🎯 সিনারিও ০২: থার্ড পার্টি অডিটরকে সাময়িক এক্সেস

প্রশ্ন: একটি বাইরের সিকিউরিটি কোম্পানি এসে ২ দিনের জন্য AWS অ্যাকাউন্ট অডিট করবে। কীভাবে এক্সেস দেবেন?

✅ সঠিক সিদ্ধান্ত: তাদের জন্য IAM User খুলবেন না! বরং একটি Cross-Account IAM Role বানাবেন এবং External ID শর্ত যোগ করবেন।

💡 কি-ওয়ার্ড ছাঁকনি পদ্ধতি (Elimination):
অপশনে যদি দেখেন "Store Access Keys in Application Code" বা "Share Root credentials"—চোখ বন্ধ করে সেগুলোকে ক্রস (বাতিল) করে দেবেন!
SCENARIO SOLVER
লেকচার ০৯ • লাইভ টেস্ট ও সমাপনী

ক্লাসরুম কুইজ ও মূল সারসংক্ষেপ

আপনি আজকের লেকচারটি কতোটা আত্মস্থ করতে পেরেছেন? নিচের প্রশ্নটির সঠিক উত্তর দিয়ে যাচাই করুন!

📝 ক্লাসরুম কুইজ:

একটি কোম্পানির ডেভেলপারকে IAM User পলিসিতে s3:PutObject (Allow) দেওয়া আছে। কিন্তু কোম্পানির প্রধান আর্কিটেক্ট AWS Organizations-এর SCP পলিসিতে ওই অ্যাকাউন্টের জন্য s3:PutObject (Deny) করে দিয়েছেন। এখন সেই ডেভেলপার S3-তে কোনো ফাইল আপলোড করতে গেলে কী ঘটবে?

A) ফাইলটি সফলভাবে আপলোড হবে, কারণ ইউজারের পারমিশন আগে কাজ করে।
B) আপলোড বাতিল (Access Denied) হবে, কারণ Explicit Deny সবসময় সবার উপরে বিজয়ী হয়।
C) আপলোড হবে, তবে ক্লাউডওয়াচে একটি ওয়ার্নিং এলার্ম রেকর্ড হবে।
