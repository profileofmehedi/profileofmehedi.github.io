System Design & Distributed Architecture

12 min read 4 sections Advanced

Fundamental principles and trade-offs for designing high-scale, distributed software systems.

Scaling & Availability Principles

Building for millions of users requires a shift in mindset.

  • Vertical vs Horizontal Scaling: Scaling up hardware vs adding more instances.
  • CAP Theorem: Consistency, Availability, Partition Tolerance. Choosing between CP and AP.
  • SLA (Service Level Agreements): Measuring availability in "Nines" (99.9%, 99.99%).

Caching Strategies for Performance

Memory is faster than disk. Caching is the primary tool for speed.

Patterns
  • Cache-Aside: Application manages the cache and DB separately.
  • Write-Through: Synchronous updates to cache and DB.
  • Write-Behind: Asynchronous updates to the database for higher write performance.
Eviction Policies
  • LRU (Least Recently Used)
  • LFU (Least Frequently Used)
  • TTL (Time to Live)

Database Architecture & Partitioning

Handling massive datasets.

  • Replication: High availability and read-scaling.
  • Sharding: Splitting data across multiple databases based on a shard key.
  • NoSQL vs SQL: Schema-on-write vs Schema-on-read trade-offs.
