# Project: WonderLab — Interactive Personal Experience Studio

## 1. Project Vision

Build a visually stunning, premium-quality, fully responsive interactive web application called **WonderLab**.

WonderLab is an all-in-one creative platform where users can explore their identity, generate personalized artwork, create beautiful Bengali quote cards, discover their names in different languages, challenge friends, visualize their life timeline, and create a professional personal portfolio.

The application must feel like a combination of a premium creative studio, an interactive digital playground, and a modern personality experience platform.

The goal is to create something so visually appealing and enjoyable that users naturally want to download their results and share them on Facebook.

This is not a generic dashboard or a basic collection of forms. Every experience must feel unique, animated, interactive, and thoughtfully designed.

## 2. Strict Technology Requirements

Use only:

- HTML5
- CSS3
- Vanilla JavaScript
- jQuery
- SVG and HTML Canvas where appropriate
- Google Fonts
- Lucide icons or inline SVG icons
- html2canvas for exporting HTML elements as images
- A suitable client-side library for downloading images when necessary

Do not use:

- Any backend
- Any database
- PHP, Python, Node.js server, ASP.NET Core, or server-side rendering
- React, Vue, Angular, or other frontend frameworks
- Any authentication or account registration
- Any paid API
- Any AI API that requires a secret key
- Any server-dependent feature

The entire application must run as a static website and be deployable directly to Cloudflare Pages, GitHub Pages, or Netlify.

Use modular JavaScript files, organized CSS, reusable functions, and a clean project structure. jQuery should be used meaningfully for UI interactions and DOM manipulation rather than being included without purpose.

All user data must remain in the browser. Use LocalStorage only where appropriate, with a clear reset option and a privacy notice.

## 3. Visual Design Direction

Create an exceptional, premium, futuristic design using:

- Modern glassmorphism
- Colorful gradient backgrounds
- Soft ambient lighting
- Blurred gradient orbs
- Subtle noise textures
- Floating decorative particles
- Animated SVG illustrations
- Beautiful rounded cards
- Soft shadows and layered depth
- Smooth hover transitions
- Elegant typography
- Micro-interactions
- Subtle 3D tilt effects
- Scroll-triggered reveal animations
- Fluid transitions between views

The visual quality should feel comparable to a polished modern SaaS landing page mixed with a playful creative studio.

Avoid a cluttered interface, excessive neon effects, unreadable text, generic templates, or too many competing gradients.

Use a consistent design system with CSS custom properties for colors, typography, spacing, radii, shadows, and animation durations.

### Color Palette

Use a coordinated palette including:

- Deep indigo
- Electric violet
- Cyan
- Coral pink
- Warm orange
- Soft lavender
- Mint green
- White and subtle neutral backgrounds

Allow each tool to have its own accent color while maintaining a consistent overall brand identity.

### Typography

Use Google Fonts:

- Hind Siliguri for Bengali text
- Inter for English text
- A suitable Bengali font weight and line-height for comfortable reading

The Bengali typography must render correctly in both the application and exported images.

### Theme

Implement Light Mode and Dark Mode.

Persist the user's theme preference in LocalStorage.

Provide smooth theme transitions without causing layout shifts.

## 4. Application Structure

Create the following pages or views:

1. Landing Page
2. Explore All Tools
3. Individual Interactive Experiences
4. Generated Result View
5. Image Export and Sharing View
6. About and Privacy section

Use a simple client-side router or an equivalent lightweight view-switching mechanism. Each experience should be directly accessible using a URL hash, such as `#fingerprint` or `#life-timeline`.

Support browser back and forward navigation where practical.

Use a mobile-first responsive layout.

## 6. Build These Eight Complete Experiences

### Experience 1: My Name Story

URL hash: `#name-story`

Purpose:

Users enter their name and generate a personalized name artwork.

Features:

- Bengali and English name input
- Name style selection
- Background and gradient selection
- Decorative particles and shapes
- Multiple artistic layouts
- Beautiful typography
- Optional subtitle or short personal message
- Animated name reveal
- Preview in real time
- Random design option
- Reset and regenerate controls

Display the name prominently in a premium artwork composition.

Include a meaning section only when a reliable, locally stored name-meaning entry is available. If the meaning cannot be verified, clearly state that the meaning is unavailable rather than inventing one.

Allow users to switch between Bengali and English text where appropriate.

Result image:

Generate a high-quality personalized name poster with a polished composition, subtle decoration, and WonderLab branding.

### Experience 2: My Digital Fingerprint

URL hash: `#fingerprint`

Purpose:

Generate a unique-looking digital fingerprint artwork based on a user's choices and questionnaire responses.

Features:

- Select personality-inspired themes such as Creative, Calm, Curious, Bold, and Explorer
- Choose primary and secondary colors
- Select a visual pattern style
- Generate fingerprint-like artwork using SVG or Canvas
- Animate the fingerprint drawing itself
- Add the user's name or initials
- Generate a short, playful description based on the selected theme
- Provide a regenerate button
- Offer multiple artistic layouts

The fingerprint is an artistic visualization, not a biometric scan or scientific personality measurement.

Use deterministic seeded randomness so the same configuration can recreate the same visual design.

The output should resemble premium digital generative art.

### Experience 3: Friendship Challenge

URL hash: `#friendship`

Purpose:

Create a fun friendship quiz that users can share with friends.

Features:

- Enter the creator's name
- Select 5–10 questions from a local question bank
- Include questions about preferences, hobbies, memories, and harmless everyday choices
- Allow the creator to choose the correct answers
- Provide a preview of the quiz
- Create a personalized quiz challenge card
- Generate a shareable challenge image
- Let the creator download the challenge image
- Allow another person to open the website and manually answer the same questions

Important limitations:

Because there is no backend, do not implement server-based quiz sessions, centralized score tracking, or persistent public quiz links.

A shared URL may contain a compact, encoded quiz configuration in a URL fragment when practical. Do not place sensitive information in the URL.

If a quiz configuration cannot fit reliably in a URL, provide a downloadable challenge image and instructions for the recipient to open the website and recreate the quiz.

Explain clearly that the image itself is not an interactive quiz and that a backend-free version cannot automatically collect friends' answers.

Make the experience feel fun and social without claiming to measure the true strength of a friendship.

### Experience 4: Your Life in Weeks

URL hash: `#life-timeline`

Purpose:

Create a visual life timeline based on the user's birth date.

Features:

- Date-of-birth input
- Optional life-expectancy assumption chosen by the user
- A grid of weeks representing an explicitly assumed time horizon
- Distinct visual states for elapsed weeks and remaining assumed weeks
- Current age calculation
- Age in years, months, and days where practical
- Life timeline visualization
- Beautiful animated progress reveal
- Optional milestone markers
- A personalized reflection message
- A shareable timeline image

Do not predict the user's lifespan or suggest that the visualization represents their actual remaining life.

Label future weeks as hypothetical and explain that the timeline is only an illustration based on the selected assumption.

Do not request the user's full name or any other unnecessary personal information.

## 7. Shared Result Card and Image Export System

Build one reusable result-card system that can be used by all eight experiences.

Each experience must have its own carefully designed output template rather than using the same generic result card everywhere.

Every result card should support:

- High-quality PNG download
- Regenerate result
- Edit result
- Copy result text where applicable
- Share through the device's native share interface when supported
- Share to Facebook using the official sharing dialog
- Save a local copy
- Return to the experience

### Image Export Requirements

Use html2canvas or an equivalent client-side technique.

For image export:

- Use a dedicated export container with a fixed aspect ratio
- Use 1080 × 1350 pixels for standard portrait social posts where practical
- Use 1080 × 1920 pixels for optional story format
- Use 1200 × 630 pixels for optional landscape previews
- Scale rendering appropriately for high-quality output
- Wait for fonts and images to load before exporting
- Handle Bengali glyph rendering carefully
- Ensure gradients and backgrounds are captured correctly
- Avoid clipping shadows or decorative elements
- Prevent the export UI controls from appearing inside the downloaded image
- Display a loading state during image generation
- Show a clear error message if image export fails

Use local fonts or ensure the required web fonts have finished loading before generating the image.

If html2canvas has rendering limitations, provide a graceful fallback instead of claiming every CSS effect will always export perfectly.

### Facebook Sharing

Implement Facebook sharing using the official sharer URL:

`https://www.facebook.com/sharer/sharer.php?u=YOUR_PUBLIC_PAGE_URL`

Important:

A static website cannot upload a locally generated PNG directly into Facebook's sharing dialog or guarantee that the image will appear as the shared post's preview.

Implement the following flow:

1. Generate the result image.
2. Let the user download the image.
3. Provide a button to share the public application URL through Facebook's sharing dialog.
4. Explain that the user can attach the downloaded image to their Facebook post.
5. Where supported, use the Web Share API with a generated image file.
6. If native file sharing is unsupported, fall back to image download and link sharing.

Never falsely claim that a local image has already been posted to Facebook.

Use the application's actual deployed URL for sharing. When running locally, disable public-link sharing or show a clear setup message.

### Privacy

Do not upload personal information or generated images to any server.

Do not embed birth dates, private quiz answers, or other sensitive details in public share URLs.

- Every result can be regenerated.
- Image download works on desktop and mobile.
- Bengali characters render correctly in downloaded images.
- Facebook sharing opens the official sharing flow.
- Native sharing falls back gracefully.
- LocalStorage features work without breaking private browsing where storage is unavailable.
- No secrets or API keys are present.
- No backend is required.
- All buttons have real working actions.
- No placeholder buttons remain.
- No broken links or missing assets.
- No browser console errors.
- No horizontal scrolling on mobile.
