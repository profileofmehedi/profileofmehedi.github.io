Stack vs Heap

Stack হলো ডেস্কটপের ছোট জায়গা — দ্রুত কিন্তু সীমিত। Heap হলো বড় গুদাম — বেশি জায়গা কিন্তু GC দিয়ে পরিষ্কার করতে হয়।

Stack (Value Types)
► Main() — চলছে

bool isAlive = true
double price = 99.5
⚡ LIFO — নিজে নিজে মুছে যায়। GC লাগে না।

→ Person { name, age }
→ List<Order> [12 items]
→ HttpClient instance
→ StringBuilder sb
♻️ GC দিয়ে পরিষ্কার করতে হয়।

Resource Management

Finalize vs Dispose

GC সব কিছু পরিষ্কার করতে পারে না — বিশেষত File Handle, DB Connection। এজন্য IDisposable প্রয়োজন।

Finalizer (~Destructor)
GC নিজে কল করে
কখন হবে অনিশ্চিত
~MyClass() { ... }
⚠️ GC overhead বাড়ায়। দেরিতে পরিষ্কার করে।
IDisposable.Dispose()
আপনি নিজে কল করেন
তাৎক্ষণিক পরিষ্কার
using (var x = new...) { }
✅ সঠিক পদ্ধতি। Resource মুক্ত করে।
IDisposable কোড ডেমো
Bad Practice
Good Practice
// ❌ Bad — Resource মুক্ত হয় না
public void ReadFile() {
    var reader = new StreamReader("data.txt");
    string content = reader.ReadToEnd();
    // Dispose() কখনো হলো না!
    // File handle ধরে রইলো চিরকাল...
}
// ✅ Good — using দিয়ে auto-dispose
public void ReadFile() {
    using var reader = new StreamReader("data.txt");
    string content = reader.ReadToEnd();
    // ব্লক শেষে Dispose() স্বয়ংক্রিয়!
} // ← এখানে StreamReader.Dispose() হয়

WeakReference<T>

Strong Reference GC থেকে অবজেক্ট রক্ষা করে। Weak Reference GC-কে অনুমতি দেয় অবজেক্ট মুছে ফেলার — Cache-এর জন্য আদর্শ।

Strong Reference
📦
MyClass obj = new();
GC এই অবজেক্ট মুছবে না — Active Strong Reference আছে।
Weak Reference
👻
WeakReference<T> wr = new(obj);
মেমোরি চাপে পড়লে GC এটি মুছে দিতে পারবে। Cache হিসেবে নিরাপদ।
Large Object Heap

LOH — Large Object Heap

৮৫ KB-এর বেশি যেকোনো অবজেক্ট সরাসরি LOH-তে যায়। GC এটি খুব কম collect করে এবং fragmentation হয়।

LOH-তে কারা যায়?
বড় Array: byte[], int[]
বড় String (85KB+)
বড় Dictionary, List
85,000+ byte-র অবজেক্ট
সমস্যা ও সমাধান
LOH fragmented হয়
Compaction ডিফল্টে বন্ধ
✅ ArrayPool<T> ব্যবহার করুন
✅ Span<T> দিয়ে Heap এড়ান
সম্পূর্ণ IDisposable Pattern
public class DatabaseConnection : IDisposable {
    private SqlConnection _conn;
    private bool _disposed = false;

    public void Dispose() {
        Dispose(true);
        GC.SuppressFinalize(this); // Finalizer দরকার নেই
    }

    protected virtual void Dispose(bool disposing) {
        if (!_disposed) {
            if (disposing)
                _conn?.Dispose(); // Managed resource মুক্ত
            _disposed = true;
        }
    }
    ~DatabaseConnection() => Dispose(false); // Fallback Finalizer
}
ArrayPool<T> — LOH এড়ানো
Bad Practice
Good Practice
// ❌ প্রতিবার নতুন বড় Array — LOH-তে চাপ বাড়ে
public void ProcessRequest() {
    byte[] buffer = new byte[100_000]; // LOH-তে যাবে!
    // ... কাজ করো
    // GC কখন collect করবে অজানা...
}
// ✅ ArrayPool দিয়ে রিইউজ করুন
public void ProcessRequest() {
    byte[] buffer = ArrayPool<byte>.Shared.Rent(100_000);
    try {
        // ... কাজ করো
    } finally {
        ArrayPool<byte>.Shared.Return(buffer); // ♻️ Pool-এ ফেরত
    }
}
