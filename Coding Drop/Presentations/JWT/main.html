Authentication — প্রমাণীকরণ
"আপনি আসলে কে?"

লগইন করার সময় username এবং password দিয়ে সার্ভারকে প্রমাণ করা যে আপনিই সেই ব্যক্তি। সার্ভার এটা যাচাই করে নিশ্চিত হয়।
উদাহরণ: ATM-এ কার্ড দিয়ে PIN দিলেন — ব্যাংক নিশ্চিত হলো আপনিই কার্ডের মালিক।
Authorization — অনুমোদন
"আপনি কী কী করতে পারবেন?"

পরিচয় নিশ্চিত হওয়ার পর আপনার Role অনুযায়ী কোন কোন জিনিসে অ্যাক্সেস পাবেন সেটা ঠিক করা।
উদাহরণ: PIN দেওয়ার পর শুধু আপনার নিজের অ্যাকাউন্ট দেখতে পাবেন, ব্যাংকের সব অ্যাকাউন্ট নয়।
JWT-এর কাজ হলো Authentication করার পর সেই পরিচয়ের তথ্য বহন করে Authorization-এ সাহায্য করা।

কেন Session ছেড়ে Token-এ গেলাম — সেটা বুঝলেই JWT-এর মূল সৌন্দর্য বোঝা যাবে

JWT মানে কী?
JSON Web Token — একটি open standard (RFC 7519) যা দুই পক্ষের মধ্যে নিরাপদে JSON তথ্য আদান-প্রদান করে
Self-Contained
টোকেনের ভেতরেই ইউজারের সব দরকারি তথ্য থাকে। বাইরে কোথাও খুঁজতে যেতে হয় না।
Tamper-Proof
ক্রিপ্টোগ্রাফিক Signature-এর কারণে কেউ টোকেনের ভেতরের তথ্য গোপনে বদলাতে পারবে না।
সর্বজনীন
Web, Mobile, Microservices — সব জায়গায় ব্যবহার করা যায়। সব বড় framework-এ native support আছে।

JWT-এর ভেতরে কী থাকে?
তিনটি অংশ — প্রতিটির ভূমিকা আলাদা
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VySWQiOiIxMjMiLCJuYW1lIjoiQWJpciIsInJvbGUiOiJ1c2VyIn0.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
Header
{"alg": "HS256", "typ": "JWT"}
কোন algorithm ব্যবহার হলো (HS256) আর এটা যে JWT — এই দুটো তথ্য থাকে।
Payload
{"userId": "123", "name": "Abir", "role": "user", "exp": 1752680000}
ইউজারের তথ্য (Claims)। শুধু Base64 এনকোড — এনক্রিপ্ট নয়! পাসওয়ার্ড এখানে রাখবেন না।
Signature
HMACSHA256( B64(header)+"."+ B64(payload), secretKey )
সবচেয়ে গুরুত্বপূর্ণ অংশ — টোকেন বদলানো হলেই এটা মিলবে না।
Claims বিস্তারিত
Payload-এর ভেতরে যে তথ্যগুলো থাকে সেগুলোকে Claims বলে — তিন ধরনের
Claim Keyনামমানে কী
issIssuerকে এই টোকেন তৈরি করেছে
subSubjectকার জন্য টোকেন (সাধারণত User ID)
audAudienceকোন সার্ভার এটা গ্রহণ করবে
expExpirationটোকেন কতক্ষণ কাজ করবে (Unix time)
iatIssued Atটোকেন তৈরির সময়
jtiJWT IDটোকেনের unique পরিচয়
roleCustomনিজের তৈরি claim — যা ইচ্ছা যোগ করা যায়
মনে রাখুন
exp claim সবচেয়ে জরুরি। এটা না থাকলে টোকেন কখনো মেয়াদ শেষ হবে না — যা বড় নিরাপত্তা ঝুঁকি।

Payload যেকেউ ডিকোড করতে পারে, তাই এখানে শুধু সেই তথ্যই রাখুন যা কেউ দেখলেও সমস্যা নেই।

বাস্তব প্রজেক্টে JWT ঠিক এভাবেই ব্যবহার হয়
Token তৈরি — Login API
public IActionResult Login(LoginDto dto)
{
 // ১. ইউজার DB-তে খুঁজে বের করুন
 var user = _db.Verify(dto);
 if (user == null) return Unauthorized();

 // ২. Claims তৈরি করুন
 var claims = new[] {
  new Claim("userId", user.Id),
  new Claim("role", user.Role)
 };

 // ৩. Token তৈরি করে পাঠান
 var key = new SymmetricSecurityKey(
  Encoding.UTF8.GetBytes(config["Jwt:Key"]));
 var token = new JwtSecurityToken(
  expires: DateTime.Now.AddMinutes(15),
  claims: claims,
  signingCredentials: new SigningCredentials(
   key, SecurityAlgorithms.HmacSha256));
 return Ok(new { token });
}

Refresh Token কৌশল
Access Token ছোট রাখুন — Refresh Token দিয়ে নবায়ন করুন, বারবার লগইন লাগবে না
১
Login সফল হলে সার্ভার দুটো টোকেন দেয়: Access Token (১৫ মিনিট) এবং Refresh Token (৭ দিন)।
২
API Call করতে Header-এ Access Token পাঠান। সার্ভার validate করে response দেয়।
৩
Access Token শেষ হলে Refresh Token পাঠান। সার্ভার নতুন Access Token দেয় — কোনো ঝামেলা নেই।
৪
Logout করলে Refresh Token DB থেকে মুছে দিন — সব শেষ, আর কোনো নতুন Token পাওয়া যাবে না।
কেন এই পদ্ধতি?
Access Token চুরি হলেও মাত্র ১৫ মিনিট ক্ষতি।
Refresh Token DB-তে থাকায় যেকোনো সময় বাতিল করা যায়।
ইউজার বারবার লগইন না করেও কাজ করতে পারে।
// Refresh endpoint
[HttpPost("refresh")]
public IActionResult Refresh(RefreshDto dto) {
 var rt = db.Find(dto.Token);
 if(rt == null || rt.Expired) return Unauthorized();
 return Ok(new { token = NewAccessToken(rt.User) });
}
নিরাপত্তার নিয়মকানুন
এগুলো ঐচ্ছিক নয় — JWT নিরাপদে ব্যবহার করতে হলে এই নিয়মগুলো অবশ্যই মানতে হবে

HTTPS ছাড়া পাঠাবেন না

HTTP-তে Token পাঠালে মাঝপথে কেউ চুরি করতে পারে। সবসময় HTTPS ব্যবহার করুন।

Secret Key সাবধানে রাখুন

কোডের মধ্যে Key লিখবেন না। Environment Variable বা Secrets Manager ব্যবহার করুন।

মেয়াদ ছোট রাখুন

Access Token ১৫ মিনিটের বেশি রাখার দরকার নেই। Refresh Token দিয়ে নবায়ন করুন।

Payload-এ গোপন তথ্য নয়

Payload যে কেউ ডিকোড করতে পারে। পাসওয়ার্ড, কার্ড নম্বর — কিছুই রাখবেন না।

httpOnly Cookie ব্যবহার করুন

localStorage-এ রাখলে JavaScript দিয়ে চুরি হওয়ার ঝুঁকি থাকে। httpOnly Cookie নিরাপদ।

Algorithm নির্দিষ্ট করুন

সার্ভারে সবসময় নির্দিষ্ট algorithm বলে দিন। "alg: none" বা অজানা algorithm reject করুন।

JWT কেন এত জনপ্রিয়?
আধুনিক আর্কিটেকচারে JWT-এর কদর এত বেশি কেন — কারণগুলো একসাথে দেখি
Stateless

সার্ভারে কিছু রাখতে হয় না — যেকোনো সার্ভার Request সামলাতে পারে।

দ্রুত

DB lookup নেই — শুধু Signature যাচাই। অত্যন্ত কম সময় লাগে।

Scalable

হাজারটা সার্ভারে ছড়িয়ে দিতে পারবেন — কোনো Shared State লাগবে না।

Microservices

একই Token দিয়ে অনেকগুলো service-এ Auth করা যায়।

সব Platform-এ

Web, Android, iOS, Desktop — সব ক্লায়েন্টে একইভাবে কাজ করে।

Open Standard

RFC 7519 — Node.js, .NET, Python, Java সব জায়গায় ready support।

আজকে যা শিখলাম
JWT মানে JSON Web Token — তিন অংশ: Header, Payload আর Signature।
Stateless হওয়ায় সার্ভারে কোনো session রাখতে হয় না — দ্রুত এবং scalable।
Signature HMAC-SHA256 দিয়ে তৈরি — Payload পাল্টালে সাথে সাথে ধরা পড়ে।
Payload এনক্রিপ্টেড নয় — সংবেদনশীল তথ্য কখনো রাখবেন না।
Access Token (ছোট) + Refresh Token — সেরা নিরাপত্তা কৌশল।
HTTPS + শক্তিশালী Secret Key + ছোট মেয়াদ = নিরাপদ JWT।
